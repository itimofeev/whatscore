# WhatScore MVP: счётчик очков для падела

Дата: 2026-09-27. Статус: на ревью.

## 1. Цель

Телефон висит на боковом стекле корта. Игрок рядом с ним одним касанием
или голосом отмечает, кто выиграл розыгрыш. Экран показывает счёт в гейме
крупно, а также геймы, сеты, подающего игрока и квадрат подачи. Случайное
очко отменяется длинным нажатием.

MVP: один телефон, полностью офлайн, без сервера. Цель: сыграть с ним
ближайшую тренировку.

Не в MVP (заложено архитектурой, реализуется позже):

- Сервер на Go: ссылка для зрителей, два телефона на одном матче.
- Смена порядка подающих внутри команды в начале сета.
- История матчей, статистика, шаринг результата.
- Bluetooth-кнопки, часы, дополнительные языки голоса.

## 2. Стек

- TypeScript, Vite, без UI-фреймворка (vanilla DOM).
- vite-plugin-pwa: манифест, service worker, офлайн-кэш.
- Vitest для тестов.
- Хостинг: GitHub Pages, деплой через GitHub Actions на push в `main`,
  собирается `web/`. Base path `/whatscore/`.
- Целевой браузер: Chrome на Android. iOS Safari должен открываться и
  считать, голос там не гарантируется.

Структура репозитория, иерархическая: верхний уровень отвечает «из чего
состоит проект», каждая папка ниже отвечает за одну область и содержит
свой README с деталями.

```
whatscore/
  README.md                 что это, из каких частей состоит, как запустить
  docs/
    superpowers/specs/      спеки и планы
  web/                      фронтенд, PWA (этот спек)
    README.md               как собрать, где что лежит
    src/
      domain/               правила счёта, чистые функции, без зависимостей
      voice/                распознавание команд и озвучивание счёта
      ui/                   экран настройки и экран матча
      storage.ts            localStorage
      main.ts               точка входа
    public/                 иконки, манифест
  go.mod                    зарезервировано под server/ на втором этапе
```

`server/` появится вместе с синхронизацией и будет устроен так же:
README и папки по областям. Никаких файлов фронтенда в корне, кроме
общего README и CI.

## 3. Модель: журнал событий

Матч = `MatchConfig` + `MatchEvent[]`. Состояние никогда не мутируется
напрямую, его вычисляет чистая функция:

```ts
reduce(config: MatchConfig, events: MatchEvent[]): MatchState
```

События:

```ts
type MatchEvent =
  | { type: 'point'; team: 0 | 1; at: number }
  | { type: 'undo'; at: number }
```

`undo` отменяет последнее ещё не отменённое `point`. Журнал только
дописывается, ничего не удаляется. Это даёт отмену на любую глубину и
позволяет позже синхронизировать журналы между телефонами. Кнопки и
голос делают одно и то же: добавляют событие. После завершённого матча
новые `point` игнорируются.

Конфигурация:

```ts
interface MatchConfig {
  teams: [TeamConfig, TeamConfig]
  firstServingTeam: 0 | 1
  deuceMode: 1 | 2 | 3 | 'advantage'   // сколько deuce до решающего очка; по умолчанию 2
  format: 'one_set' | 'best_of_3' | 'best_of_3_super_tb'  // по умолчанию best_of_3
  swapZonesWithSides: boolean           // по умолчанию true
  voice: VoiceConfig
}

interface TeamConfig {
  name: string                // по умолчанию 'Red' и 'Blue'
  players: [string, string]   // players[0] подаёт первым в команде
}

interface VoiceConfig {
  enabled: boolean            // по умолчанию false, включается в настройках
  announce: boolean           // озвучивать счёт после каждого очка, по умолчанию false
  lang: 'en' | 'ru'           // по умолчанию 'en'
}
```

Состояние, которое отдаёт `reduce`:

```ts
interface MatchState {
  sets: Array<[number, number]>          // завершённые и текущий сет, геймы
  game: GameScore                        // текущий гейм или тай-брейк
  server: { team: 0 | 1; player: 0 | 1; side: 'right' | 'left' }
  decidingPoint: boolean                 // следующее очко решает гейм
  swapped: boolean                       // команды поменялись сторонами
  finished: { winner: 0 | 1 } | null
  canUndo: boolean
}

type GameScore =
  | { kind: 'game'; points: [Pts, Pts]; deuces: number }   // Pts: 0 | 15 | 30 | 40 | 'AD'
  | { kind: 'tiebreak'; points: [number, number]; target: 7 | 10 }
```

## 4. Правила счёта

Гейм:

- Очки 0, 15, 30, 40. Гейм выигран при 4+ очках и разнице 2, с учётом
  правила deuce ниже.
- Deuce: каждый раз, когда счёт становится 40:40, счётчик deuce в гейме
  растёт на 1. Если `deuceMode` число N и счётчик достиг N при равном
  счёте, следующее очко решающее: его победитель берёт гейм.
  N=1 golden point, N=2 любительский вариант (первый deuce с advantage,
  второй решающий), N=3 Star Point по правилам FIP 2026.
  `'advantage'` без ограничения.
- Решающее очко подсвечивается, принимающие выбирают сторону сами,
  приложение это не контролирует.

Сет и матч:

- Сет до 6 геймов с разницей 2. При 6:6 тай-брейк до 7 с разницей 2,
  сет засчитывается 7:6.
- `one_set`: один сет. `best_of_3`: до двух выигранных сетов.
  `best_of_3_super_tb`: при 1:1 по сетам вместо третьего сета
  супер-тай-брейк до 10 с разницей 2, записывается как сет 1:0.

Подача:

- Ротация из четырёх игроков: `[T1p0, T2p0, T1p1, T2p1]`, где T1 это
  `firstServingTeam`. Ротация фиксируется на весь матч.
- Гейм с глобальным номером n (сквозной по всем сетам, тай-брейк
  считается одним геймом) подаёт игрок `rotation[n % 4]`. Новый сет
  ничего не сбрасывает: подаёт следующий по ротации. Это автоматически
  даёт правило FIP «после тай-брейка сет начинает команда, которая
  тай-брейк не начинала».
- Тай-брейк с глобальным номером n: очко 0 подаёт `rotation[n % 4]`,
  затем каждые два очка подающий сдвигается по ротации:
  очки 1-2 `rotation[(n+1) % 4]`, 3-4 `rotation[(n+2) % 4]` и т.д.
- Квадрат подачи: правый при чётной сумме очков в гейме или тай-брейке,
  левый при нечётной.

Смена сторон:

- В сете стороны меняются после 1-го гейма сета и далее после каждого
  нечётного, а также в конце сета, если сумма геймов сета нечётная.
  В тай-брейке дополнительно после каждых 6 очков.
- `swapped` = чётность общего числа смен с начала матча.

Отмена:

- `undo` возвращает состояние ровно к моменту до последнего очка,
  включая счётчик deuce и подающего. Это следует из того, что
  состояние вычисляется из журнала.

Модуль `domain` не имеет внешних зависимостей и покрыт табличными
тестами: минимум по одному сценарию на каждый пункт выше, плюс
полный матч от первого очка до победы для каждого формата.

## 5. Экраны

### Настройка матча

Одна страница с полями: имена команд, имена игроков, кто подаёт
первым (команда и игрок), режим deuce, формат, зоны меняются со
сторонами, голос вкл/выкл, озвучивание вкл/выкл, язык голоса. Все поля
имеют дефолты, кнопка Start работает сразу. Последние настройки
сохраняются и подставляются в следующий раз. Если в хранилище есть
незавершённый матч, страница открывается сразу на нём с кнопкой
«New match».

### Матч

- Раскладка горизонтальная по умолчанию: манифест PWA задаёт
  `orientation: landscape`, в установленном приложении экран
  фиксируется. В браузере без установки вертикальная ориентация тоже
  работает, той же раскладкой.
- Экран делится на две зоны, левую и правую, во всю высоту. Каждая зона
  это одна команда. При `swapZonesWithSides` зоны следуют за `swapped`,
  чтобы команда слева на экране была слева на корте с точки зрения
  человека у телефона.
- В зоне: очки в текущем гейме максимально крупно, это главный элемент
  экрана. Под ними имя команды, геймы текущего сета и счёт по сетам
  мелко. В тай-брейке крупно показываются очки тай-брейка.
- Короткое касание зоны: очко этой команде. Длинное нажатие (600 мс) на
  любой зоне: отмена последнего очка, с визуальным индикатором
  заполнения во время удержания и вибрацией по срабатыванию. Отдельной
  кнопки отмены нет.
- Полоса подачи по центру: имя подающего игрока, стрелка или подсветка
  на его команду, квадрат подачи R или L. При решающем очке полоса
  меняет цвет и пишет «Deciding point» (или «Golden point» при N=1,
  «Star point» при N=3).
- После каждого очка на 2 секунды всплывает подтверждение «Point Red».
- Индикатор микрофона и кнопка выключить голос прямо на экране матча,
  небольшая, в углу. Кнопка выхода в настройки там же, с подтверждением.
- При старте матча: запрос fullscreen и Wake Lock. Если Wake Lock
  оборвался (свернули приложение), запрашивается заново при возврате.
- Конец матча: экран с результатом по сетам, кнопки «New match» (те же
  настройки) и «Undo» на случай ошибочного последнего очка.

Интерфейс на английском.

## 6. Голос

Распознавание:

- Web Speech API (`SpeechRecognition`), `continuous: true`,
  `interimResults: false`, язык из настроек. Работает только с
  интернетом, это ограничение Chrome на Android.
- Chrome прекращает слушать после паузы; по событию `end` распознавание
  перезапускается, пока голос включён и матч не завершён.
- Команды, транскрипт нормализуется в нижний регистр и ищутся
  подстроки:
  - очко: `point <team name>` / `<team name> point`, а также
    `point one` / `point two` как запасной вариант независимо от имён.
    По-русски `очко <имя>`, `<имя> очко`, `очко первым` / `очко вторым`.
  - отмена: `undo` / `отмена`.
  - произнести счёт: `score` / `what's the score`, по-русски `счёт` /
    `какой счёт`. Работает всегда, когда голос включён, даже если
    автоматическое озвучивание после очка выключено.
- Если транскрипт содержит обе команды или не распознан, ничего не
  происходит. Ложные срабатывания страхуются длинным нажатием отмены.
- Голосовое очко показывает то же подтверждение «Point Red».
- Во время озвучивания счёта распознавание ставится на паузу, чтобы
  телефон не слышал сам себя.

Озвучивание (`speechSynthesis`, работает офлайн):

- После каждого очка при `announce`: счёт гейма, счёт подающей команды
  первым: «fifteen love», «thirty all», «deuce», «advantage Red»,
  «deciding point». При выигрыше гейма: «game Red, three two». При
  выигрыше сета: «set Red». В тай-брейке цифры: «five three».
- По команде `score` то же самое по запросу, независимо от `announce`.
- Русские фразы аналогичны.

Риск: поведение Chrome при частых перезапусках слушания и в шуме корта
проверяется на первой тренировке. Если распознавание окажется
непригодным, MVP остаётся полезным на касаниях.

## 7. Хранение и PWA

- `localStorage`: ключ `whatscore.match` с `{ config, events }` текущего
  матча, ключ `whatscore.lastConfig` с последними настройками. Запись
  после каждого события. Чтение и запись обёрнуты в try/catch.
- Манифест: standalone display, `orientation: landscape`, иконка.
  Service worker кэширует все ассеты, приложение открывается без сети.
- Сборка и деплой: GitHub Actions на push в `main`, публикация `dist`
  в GitHub Pages.

## 8. Тестирование и проверка

- `domain`: Vitest, табличные тесты по разделу 4 плюс сквозные матчи.
- `voice`: парсер команд тестируется таблицей транскриптов на двух
  языках. Сами Web Speech API в тестах не вызываются.
- `ui` и `storage`: проверка Claude Code в Chrome с эмуляцией телефона
  в горизонтальной ориентации
  до передачи Илье: касания, длинное нажатие, перезагрузка страницы с
  восстановлением матча, смена зон местами.
- На реальном телефоне на корте проверяет Илья: голос в шуме, Wake Lock,
  fullscreen, читаемость на солнце.
